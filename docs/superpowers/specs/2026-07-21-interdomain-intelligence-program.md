## 3. Proposals (final, post-counter-review)

### Axis A — Conversational core
- **P1 — RAG Spaces as an active domain.** New routable domain `document` (result_key `documents`) + `search_user_documents_tool` (multi-query, per-space filter, read-only, no HITL) + taxonomy entry + manifest + registry card type. Unlocks planner/ReAct iteration over user documents and cross-domain combination (documents × email × Drive).
- **P2 — Cross-conversation recall** (BACKLOG). Embedding index over persisted assistant messages + registry widget payloads; internal non-routable tool `recall_from_history`; re-injection into the live registry (widget rehydration mechanism exists in `data_registry/message_widgets.py`). Blocked on open decisions: retention/PII alignment, index scope. Treat like the encryption socle: decisions first, NO-GO until arbitrated.
- **P3 — Person-360 pivot.** Cross-domain tool `get_person_overview(person)` orchestrating (briefing pattern, one session per fetcher): contact card, recent emails, shared events past/upcoming, shared files, memories matching `trigger_topic`, linked reminders. Option: nullable `linked_contact_id` on `Memory` (migration) filled by the extractor when the person resolves — seed of a light personal graph.
- **P4 — Adjacency matrix completion + chaining few-shots.** Fix the false `task` comment (doc-contradiction bug); add the missing high-value pairs (task↔event, email→file); add planner/ReAct few-shots for 4 chains: place→telephony (book a table), event→route+weather (leave on time), email→file (attachments), task→event (block a slot). Measure token impact (matrix feeds initiative-node prefilter).

### Axis B — Proactive loops
- **P5 — Open loops / commitments ledger** ⭐ (program pillar #1). New `open_loops` table {subject, counterparty, direction (me→them / them→me), implicit deadline, source ref}; extractor added to the existing post-response extraction pipeline (`response_node.py::_schedule_post_response_extractions`); 12th heartbeat source; briefing section (consumed by Lot 4). Closure: email-thread reply detection (arbitrate v1 vs v2 — periodic thread scan costs API), conversational confirmation, soft expiry. ADR required. Flag `OPEN_LOOPS_ENABLED`. J+14 measurement.
- **P6 — Smart departure alert.** New heartbeat source `_fetch_departure_advice`: next located event within N hours → Routes ETA from effective location (`get_effective_location_for_proactive`) → decision prompt can draft "leave by 14:10 (25 min, rain at 14:30)". Budget: max 1 event/cycle, Redis ETA cache, short-circuit without connector.
- **P7 — Birthdays as proactive source + action chain.** Extract `fetch_birthdays` to a shared service (DRY), add as heartbeat source; notification proposes the chained action (draft message / phone call) via existing draft flows.
- **P8 — Dynamic memory query in heartbeat 2nd pass.** Move `_fetch_memories` to the 2nd pass with the same dynamic query as journals (embedding computed once, shared). Closes the ADR-135 asymmetry.
- **P9 — Local/temporal grounding of interests.** Probabilistic "local events" generation variant (1 cycle out of N): inject city (existing effective-location resolution, existing opt-in) + upcoming weekend window into the Brave/Perplexity query; "near you" badge.
- **P10 — Extended attention ledger.** Include scheduled-action results, reminders, and telephony reports in the heartbeat anti-redundancy window (union query) + optional per-user global daily budget.

### Axis C — Learned automation
- **P11 — Scheduled actions from chat** ⭐ (program pillar #2). Routable domain `automation` + create/list/toggle/delete tools + HITL draft type `SCHEDULED_ACTION` (pattern: PHONE_CALL draft) + registry type + widget card + taxonomy/manifests. Arbitrate: HITL level (recommended: confirmable draft).
- **P12 — Recurrence detection → automation suggestion.** On stable signature (same intent+domains, similar hours, ≥N occurrences over M days — thresholds in settings, never hardcoded), initiative node proposes automating → P11. Reuses plan-pattern-learner data + timestamps.
- **P13 — Contextual skill suggestion.** (a) heartbeat: important meeting with attendees <2h → propose `preparation-reunion`; (b) initiative node: recurring overdue tasks → propose `coaching-productivite`. Deep-link to chat with prefilled prompt. Placement: Lot 3 optional or detached (user to decide).
- **P14 — Post-call derived actions** (REQUALIFIED — smaller than initially stated). The extraction layer EXISTS (`StructuredCallData`); missing piece only: when `agreed` + `proposed_datetime` → derive a prefilled EVENT/TASK HITL draft in the return flow instead of text-only proposal.

### Axis D — Synthesis & continuity
- **P15 — Briefing 2.0.** (a) "For you" card: interest of the day (via ledger, deduplicated) + overnight scheduled-action digest + open loops (P5); (b) portrait-informed synthesis (`build_journal_user_model_block(format="brief")` — designed for this); (c) actionable cards: each item deep-links to `/dashboard/chat` with a prefilled prompt ("reply to this email", "prepare this meeting"). Frontend-heavy: i18n ×6 parity, a11y/hooks ratchets, vitest.
- **P16 — Longitudinal health×agenda conditioning** (REQUALIFIED — low priority). Ad-hoc same-day correlation ALREADY exists (decision prompt rule 17). Only missing: baseline conditioned on agenda load ("steps drop 40% on 6+-meeting days"). Strictly factual, never advice (health domain contract). Re-evaluate after Lots 1–4 measurements.
- **P17 — Psyche curiosity → interest exploration** (low priority). Bounded modulation of `pick_varied_sample` exploration ratio by `drive_curiosity`. Character-coherence value; revisit late.
