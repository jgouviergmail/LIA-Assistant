# Jev integration — lot 1

Status: lot 1 and requested JEV debug extension implemented, verified and reviewed;
ready for the owner's dev acceptance. Branch: `codex/jev-lot-1`.

The owner requires one deployment per lot, after their own dev acceptance.
This work stops after lot 1 is implemented, verified and reviewed. No production
deployment, commit or push is included. Execution and adversarial review are inline.

## Scope

1. Native TypeSafe Choice client with deadlines, strict response validation,
   actual input/output accounting and bounded provider failures.
2. TypeSafe provider, pinned Jev model and token tariff in the existing LLM
   configuration/pricing catalogue. A `decision` kind cannot occupy a chat slot.
3. Administration section with global and per-usage switches, all initially off.
   OFF makes no Jev call. A failed/uncertain ON attempt falls back to the currently
   configured existing path. No future-lot switches are offered prematurely.
4. Meeting template selection only: preserve explicit meeting and user choices,
   candidate ownership and exclusions; Jev may select only from the same candidates.
5. Correct semantic evidence projection (short content, false flags, nested dates,
   complete participant relationships) while retaining provenance and technical-data
   exclusions. Do not replace the voice/display summarizer.
6. Metrics for attempted/actual paths, latency and fallback; operational documentation.
7. Account-scoped, temporary debug feed for each native call: bounded context,
   readable response, caller and actual consumer branch, including background runs.

## Design constraints

- Routing settings use the existing `system_settings` store and admin audit trail.
  Read all relevant flags in one database snapshot per operation, without a Redis
  dependency. A completed update applies to future reads; in-flight work retains its
  snapshot. Serialize writes so concurrent first writes and audit old values are sound.
- Native decisions are not `BaseChatModel` instances. Native HTTP resources have a
  bounded lifetime; redirects are refused. Do not add sampling/reasoning parameters.
- Keep each billed model's usage separate. Never add Jev counters to a token capture
  later priced as the synthesis model. Both quota ceilings apply before spending.
- The new transport is owned by a registered usage, cannot run while OFF, and must
  record billed unsuccessful answers before fallback. No content or secret in logs.
- No database transaction remains open during provider calls.
- UI uses existing settings primitives and typed API hooks, with six-language labels,
  keyboard/focus preservation, mobile reflow and actionable save/configuration errors.
- Provider/model changes never silently enable an optimization.

## Requested extension: JEV debug panel

The native runtime captures the account's own calls independently of chat SSE.
The meeting selector updates the same attempt with its real branch. The existing
debug access policy is shared by streaming, public status, collection and reading.
The UI uses the existing accordion, typed query hook, error boundary and six
locales. Opening it reads the temporary feed; closing aborts and discards it.

Inline cold review covered ownership, inactive accounts, hot permission revocation,
raw provider errors and credentials, bounded Unicode context, cancellation,
accounting failures, Redis outages, retention, keyboard access and responsive
layout. Reproduced defects were corrected before hand-off:

- A long context was not keyboard-scrollable; it is now a named focusable region.
- The viewport guard rejected a `vh` height; the feed now uses the dynamic
  viewport unit required by the application's responsive layout contract.
- A failed call was labelling its requested model as a reported model. The
  reported field now stays absent unless the provider actually supplied it;
  the billing fallback to the configured tariff is unchanged.
- The new Redis family was missing from account/reset purges; it now follows the
  common user-cache registry and its existing identifier scan conventions.
- A delayed initial write could overwrite a confirmed action. An atomic finality
  check now rejects that regression; content remains encrypted, and the only clear
  metadata added to the stored envelope is the finality bit.
- Hash-level TTL alone could retain an older encrypted body while newer calls
  kept the hash alive. Redis field expiry now fixes its absolute deadline to the
  original call start, tested against the real Redis expiration metadata.
- The public demonstrator's route census required a written decision for the
  new diagnostic endpoint. Its edge keeps it internal; no enabled JEV usage
  exists in the demonstrator's capability set.
