## Resume and publication contract

1. Retain the image report and its unresolved upstream risks. Do not infer safety from an absent fix or add an unevidenced exception. Required CI, Security and disposable-installer gates must pass on the publication SHA.
2. Reconcile concurrent changes, preserve the initial scope, and refresh the actual release date and landing time once publication becomes possible. Refresh measurements and affected tests when their owning source changed.
3. Finish `task test:install` and the defaults-to-Settings guard on that snapshot. Keep both green before a tag.
4. Review the final staged snapshot, commit and push through the normal hooks, and verify CI and Security on the exact pushed SHA. Never use `--no-verify`.
5. Build the immutable v4.3.0 candidate, qualify all four native amd64/arm64 × local/prebuilt installer legs and promote the same verified digests through the release workflow.
6. Execute `task deploy:prod`, `task demo:prod:down`, `task demo:prod:up`, `task demo:prod:verify` in that order. Verify readiness, runtime version and revision.
7. Verify the published v4.3.0 assets and provenance. Close only resources owned by this qualification.
