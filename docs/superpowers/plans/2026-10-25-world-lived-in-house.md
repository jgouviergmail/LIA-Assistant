# Lived-in house implementation plan

Spec: [owner room brief](../specs/2026-10-25-world-lived-in-house-design.md).

Execute inline in the existing external worktree. Preserve main, junctions and concurrent work. Do not install dependencies, transfer API secrets, merge or deploy. Publish each usable iteration through the existing isolated preview and clean only owned temporary Docker resources.

## Lot 1 — Typed activity and confirmed-seat contracts

1. Add discriminated destinations for generated-file family, native embedded workspaces, explicit unsent drafts and LIA's four choices.
2. Add optional initial-family input to the existing gallery; test normal URL compatibility and explicit override.
3. Add a bounded pending-seat activity state machine. Consume only the server-confirmed requested pose under the same controller/account lifetime.
4. Test refusal, occupancy, interrupted approach, reconnect, duplicate acknowledgment, stand and account withdrawal.

## Lot 2 — Spatial plan and furniture

1. Re-author connected room sizes and openings around the larger central hall, with nearby terrace/garden and separate private studio.
2. Add modular object painters, explicit semantic symbols, correctly facing furniture, multi-seat benches and prescribed room inventories.
3. Compile the new server collision/pose catalogue with a new scene version.
4. Prove clear circulation and all activity/pose approaches. Inspect at play zoom on desktop/mobile before publishing.

## Lot 3 — Native embedded workspaces

1. Reuse settings activity components where complete.
2. Extract/reuse Relations, Meetings and Workboard workspaces; keep route shells compatible and navigation inside the embedded host.
3. Integrate alerts, LIA journal and psyche choices; preserve native availability, privacy, quotas and HITL.
4. Real browser verification of generated-file tabs, call/image drafts, memory edit, meeting access, relations and workboard.

## Lot 4 — Widgets and ambient life

1. Reuse radio command and add account-owned smartphone arrivals with separate SMS/reminder indicators.
2. Add date/time and weather access; isolate settings from activities.
3. Add bounded arcade/TV animation, roaming cat, daytime birds and sunny daytime butterflies, with reduced-motion/quality controls.
4. Test notification identity/deduplication/lifetime, silent/no-provider navigation and environmental gating.

## Lot 5 — Adversarial qualification and handover

1. Review all code paths for privacy, authority races, inaccessible geometry, allocations, leaks and inherited failures.
2. Run relevant frontend/backend unit/integration tests, native Chromium/Firefox/WebKit journeys and mobile/keyboard/visual checks.
3. Complete required lint, type, catalogue, locale, coverage and documentation gates; ratchets only tighten from measurements.
4. Verify source parity with the published preview, record evidence and limitations, remove owned temporary resources and retain the usable preview.


## Owner refinement within lot 2 and lot 4

Apply the subsequent room/furniture corrections through the shared authored catalogue, not per-route hardcoding. Regenerate the server geometry from that same source; preserve stable semantic and customization anchor identities.

Validate front-only external access, the continuous hall, visible restroom, studio path, meeting-screen support, window-safe wall mounting, lamp supports, easel/chair visibility, opposing outdoor seating and pond/path separation. Test double-click/tap recognition, cancellation and server-accepted running independently of cosmetics.

Qualify native owner-only notification arrivals, the cached weather display and the no-provider behavior. Keep a complete [refinement report](../qualification/2026-10-25-world-house-refinement.md), including diagnostic failures, current successes and remaining physical-device boundaries.
