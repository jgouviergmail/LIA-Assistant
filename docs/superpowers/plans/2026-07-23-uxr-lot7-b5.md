# UXR Lot 7 — B5: Open-Loops Management View Implementation Plan

> Executed INLINE (program mandate). Program doc §Lot 7 (arbitrations 4a settings
> section, 5a no source column).

**Goal:** lightweight consult/close surface for the commitments ledger (ADR-139):
settings section grouped by direction, one-tap Fait / Relancer / Plus d'actualité,
Prometheus closure counters. No manual creation (the ledger's value is being
automatic).

## Backend
- B1 Metrics chokepoint: `open_loop_closures_total{action}` in metrics_registry
  (`track_open_loop_closure`), emitted with `suppress` INSIDE
  `OpenLoopRepository.close_loop` (covers router + conversational extractor in one
  place — action = closed_reason) and `expire_stale_loops` (expired, by count).
- B2 Router: optional body `CloseLoopRequest {action: Literal['done','dismissed'] =
  'done'}` mapped to closed_reason `api`/`dismissed`; repository docstring updated
  (free String(40), no CHECK — verified). Tests: mapping, default, invalid → 422,
  ownership 404, metric emitted.

## Frontend
- F1 `useOpenLoops` (404-tolerant when the router is unmounted: error → unavailable),
  `closeLoop(id, action)` optimistic with restore-on-error.
- F2 `OpenLoopsSection.tsx` (settings; rendered only when
  `config.features.open_loops_enabled` — Lot 6's flag): two direction groups, rows =
  subject + counterparty + due badge (browser tz) + days-open badge; actions Fait /
  Relancer (`chatDraftHref` + existing `dashboard.briefing.intents.loop_*` keys) /
  Plus d'actualité. No source column (5a). Cap note when total==100.
- F3 ForYouCard loops heading → Link to settings.
- F4 i18n ×6 (section + actions + empty state + count), a11y (actions named with
  subject), tests: grouping/sort pure helpers, actions incl. 404-restore, gating.

Gates: backend fast+lint; frontend suite+tsc+lint+coverage+ratchets; runtime: dev
flag ON — list a QA loop (INSERT), close via UI (done + dismissed), counters visible
in /metrics, section absent when flag off (config).
