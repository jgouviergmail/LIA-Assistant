# UXR Lot 3 — A3: Scroll-to-Bottom + Reading Invariant Implementation Plan

> **For agentic workers:** executed INLINE (program mandate). Program doc:
> `docs/superpowers/specs/2026-07-22-ux-refinements-program.md` (Lot 3 spec + edge register).

**Goal:** floating scroll-to-bottom button (↓ + "new response" badge, historyView
delegation) and the NEW invariant: a streaming answer never yanks a reader who scrolled
away. Own sends still jump to the sent message (preserved behavior, now explicit).

**Architecture:** pure decision helpers + a scroll-UI reducer in a new module
(`lib/chat-scroll.ts`), a presentational `ScrollToBottomButton`, and a surgical edit of
`ChatMessageList`'s auto-scroll effect (live geometry measured AT DECISION TIME — never a
cached flag). Load-time machinery (initial pin loop, prepend preservation,
gesture-armed pagination observer) stays byte-identical.

**Oracle strategy (pinned by the repo itself):** jsdom scroll-geometry oracles were
deliberately removed (`ChatMessageList.test.tsx:170-182` — they passed green against
no-op fixes). Therefore: vitest covers the pure helpers/reducer + button props/aria;
the behavioral invariant is proven in the hermetic e2e package with a **gate-promise SSE
mock** (the route handler awaits a test-controlled promise → deterministic "tokens land
while the reader is away"). Baseline: `chat-initial-scroll.spec.ts` 3/3 green pre-change
(verified 2026-07-22 against the dev container).

## Decision table (decideFollow)

| Case | atBottom | last message | Decision |
|---|---|---|---|
| Own send | any | NEW id, role=user | follow (your message must appear) |
| Streaming token / content growth | true | same id | follow (classic follow-the-stream) |
| Streaming token while reading | false | same id | stay |
| New assistant/proactive arrival | false | NEW id, role≠user | stay + badge +1 (once per id, arrival OR completion — `countedIdRef` dedupes) |
| End-of-stream alignment | false | — | stay (+1 if this response was never counted) |
| End-of-stream alignment | true | — | align to last user message (today's behavior) |

Badge resets whenever the reader reaches the bottom (scroll or button). In `historyView`
the button always shows and delegates to `returnToPresent()` (QW-2 semantics; the QW-2
banner is KEPT — recorded interpretation: the button is the return affordance, the banner
the state explanation; removing the banner would regress QW-2 tests for no UX gain).

### T3 — ChatMessageList integration
- Auto-scroll effect: measure live, decide via `decideFollow`; gate BOTH the else-branch
  follow and the end-of-stream alignment; maintain `prevLastMessageIdRef` +
  `countedIdRef` on every early-return path (justPositioned, wasPrepend included);
  `settledRef` set at first successful pin.
- Passive rAF-throttled scroll listener on the resolved scroller (attach when list
  non-empty, guarded by `settledRef`) → dispatch `distance`.
- Sticky wrapper before `messagesEndRef` (`sticky bottom-2 z-10 flex justify-center
  pointer-events-none`); show when `historyView || away`.
- Click: historyView → `onReturnToPresent()`; else `pinToBottom` + reset.
- sr-only polite live region announcing the badge count.
- New props `historyView?: boolean`, `onReturnToPresent?: () => void`.
