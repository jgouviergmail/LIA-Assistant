# UXR Lot 2 — A7: Persistent Input Draft + ↑ Recall Implementation Plan

> **For agentic workers:** executed INLINE (program mandate). Program doc:
> `docs/superpowers/specs/2026-07-22-ux-refinements-program.md` (Lot 2 spec + edge register).

**Goal:** the chat input text survives refresh/navigation (per-user debounced
localStorage), is cleared on send and logout; ArrowUp in an empty input recalls the last
sent user message. Frontend only.

**Architecture:** a `useInputDraft(userId)` hook owns storage (debounced save, immediate
clear on empty, flush on unmount, clamp at the new `CHAT_INPUT_MAX_LENGTH` mirror
constant); the page wires it through the existing `onMessageChange` path and the
`initialMessage` prop (priority `?draft=` > stored). `ChatInput` gains `lastUserMessage`
+ the ArrowUp branch and the missing `maxLength`.

**Verified precondition:** the dashboard layout gates auth (`layout.tsx:91-104` spinner /
null) — `ChatPage` mounts only with `user` set, so the one-shot draft read at mount is
reliable and SSR never renders a drafted textarea (no hydration mismatch).

## Global constraints

- Storage: user content only, never session material (BFF invariant untouched); purge on
  logout; try/catch every storage access (private mode); key
  `lia.chatDraft.{userId}`.
- `CHAT_INPUT_MAX_LENGTH = 10_000` mirrors backend `ChatRequest.message` max_length
  (`agents/api/schemas.py:112`) — cross-referenced comments both sides of the mirror.
- Empty value clears **immediately** (cancels pending debounce) — a refresh right after
  send must never resurrect the sent text.
- Pending save **flushes on unmount** — navigating away within the debounce window must
  not lose the last keystrokes.
- ↑ recall: only `value === ''` && `!e.nativeEvent.isComposing` && a last user message
  exists; no cycling (v1); caret placed at end; guard designed so Lot 8 can also suppress
  it while the slash menu is open.
- Future C2 aparté: `useInputDraft(userId, enabled)` — `enabled: false` = full no-op.
