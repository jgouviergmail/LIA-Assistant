# UXR Lot 4 — A2: Follow-up Chips Implementation Plan

> Executed INLINE (program mandate). Program doc:
> `docs/superpowers/specs/2026-07-22-ux-refinements-program.md` (Lot 4 spec + edge
> register + arbitration 1a: 2-3 chips via schema extension, token cost accepted).

**Goal:** 0–3 tappable follow-up suggestions under the latest assistant response,
generated by the Initiative node (ADR-062) in the user's language, riding the QW-5
metadata rail (done chunk + archived `message_metadata`), prefilling the input on click —
never auto-sent.

**Key simplification found in-code:** the graph `state` IS readable in
`agents/api/service.py` at archive time (idiom `state.get("injected_journal_ids")`,
service.py:1191) → NO pop-once cache; the service reads
`state.get(STATE_KEY_INITIATIVE_FOLLOWUPS)` directly and enriches both the archived
metadata (branch-free enricher idiom `with_persisted_trace`) and `done_metadata`.

## Backend tasks (TDD)

### B1 — Constants + state key
- `core/constants.py`: `STATE_KEY_INITIATIVE_FOLLOWUPS = "initiative_followups"`,
  `INITIATIVE_FOLLOWUPS_MAX = 3`, `INITIATIVE_FOLLOWUP_MAX_CHARS = 200`.
- `agents/models.py` (`MessagesState`): declare `initiative_followups` (same optionality
  idiom as sibling initiative keys — undeclared keys are silently dropped by LangGraph).
- `core/field_names.py`: `FIELD_FOLLOWUP_SUGGESTIONS = "followup_suggestions"`.

### B2 — New module `services/streaming/followup_metadata.py` (tests first)
- `sanitize_followups(raw: list[str] | None) -> list[str]`: strip whitespace + inner
  newlines→space, drop empties, dedupe (case-insensitive), cap at
  `INITIATIVE_FOLLOWUPS_MAX`, each clamped to `INITIATIVE_FOLLOWUP_MAX_CHARS`.
- `with_followup_suggestions(metadata: dict, suggestions: list[str]) -> dict`:
  branch-free enricher (returns metadata unchanged when list empty; NEW dict otherwise).
- Tests: `tests/unit/domains/agents/services/streaming/test_followup_metadata.py`.

### B3 — Initiative node (extend `test_initiative_node.py`)
- `InitiativeDecision.followup_suggestions: list[str] = Field(default_factory=list, ...)`
  (strict-mode safe — same pattern as `InitiativeAction.parameters`).
- `_initiative_core`: `state_update[STATE_KEY_INITIATIVE_FOLLOWUPS] =
  sanitize_followups(decision.followup_suggestions)` written in the SAME places the
  suggestion is handled (step 7 — also when should_act=False), only when non-empty.
- Prometheus: `initiative_followups_total` counter (+= len) in metrics_agents, emitted
  under `suppress` beside the existing initiative metrics.
- Debug surface (program rule): include `followup_suggestions` in the
  `STATE_KEY_INITIATIVE_RESULTS` entry dict (existing initiative debug panel section
  shows it — no new panel plumbing).
- `initiative_recurrence.py`: verify passthrough (it spreads `state_update`) — test.

### B4 — Prompt v1 (`prompts/v1/initiative_prompt.txt`)
- Add an instruction block: ALWAYS propose 0–3 short follow-up queries (≤ ~12 words

- JSON schema example in the prompt updated if it enumerates fields.

## Edge register (from the program doc — enforce in tests)
- Conversation-route turns / skill turns / HITL-just-resolved / max-iterations: no key →
  chips absent everywhere (tolerated).
- ReAct: reached via react_finalize edge — covered by design; assert passthrough test.
- Initiative loop iterations: last write wins.
- Markdown/HTML/newlines/duplicates/overlength in suggestions: sanitized (B2) + text
  children only (F2).
- Chips hidden while input disabled; disappear when a newer turn starts (latest-only
  gate); reload persistence via archived metadata (latest-only gate keeps the
  "until a new turn" contract).
