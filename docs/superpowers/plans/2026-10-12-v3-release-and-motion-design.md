# LIA v3.0.0 delivery plan

The user authorized implementation, all release qualification, commits and push,
production deployment, demonstrator restart and verification, publication, and
the specified preference update for every production account. This plan tracks
delivery; its presence does not claim qualification or deployment.

## Delivery sequence

1. Preserve and inventory the starting checkout, every commit after v2.6.1,
   and every uncommitted application change. Map each change to product copy,
   architecture decisions, implementation documentation and installer contracts.
2. Finalize the motion production: stationary application screens outside
   explicit native-element focus, clear informal French, the LIA editorial
   palette, the complete selectable avatar catalogue, a substantial PWA scene,
   and a populated scheduled-action planning view with native status colors.
3. Review representative frames and transitions, rerender every affected
   composition, package and verify actual delivery files, and preserve the
   editable construction and provenance. Keep musical source and attribution.
4. Add the blue Presentation CTA before the guided demonstration CTA. Remove
   the neighboring registration CTA. Open the complete film in an accessible,
   exclusive fullscreen dialog with deterministic keyboard focus and playback
   cleanup. Publish operator-hosted media and link the complete film in README.
5. Document production, dependencies, rendering, review, publication and
   evolution. Remove only identified owned temporary or superseded files after
   protecting the active media, source archive and necessary provenance.
   After finalizing the film, improve the phone landing: more space above and
   below the personal-assistant promise and a separator; the three trust items
   centered on individual lines with separators above and below; a separator
   below the journey-benefit panel; application screenshots using the same
   carousel behavior and presentation as the Grafana screenshots.
6. Complete missing ADRs and affected technical/user documentation. Update
   all six locales, FAQ and its user/admin changelog, relevant durable landing
   presentations, blog material, settings search vocabulary, knowledge exports,
   and functional/technical/decision maps from current contracts.
7. Bump all declared version surfaces to 3.0.0 with the Paris editorial date
   and time. Update README and CHANGELOG with source-backed features and fixes;
   use fresh measurements for public metrics and qualify standards claims.
8. Run the actual pre-commit hook and address every diagnostic. Complete the
   full relevant static, coverage, behavioral, integration and browser gates,
   installer tests and the defaults-to-Settings guard before tagging. Preserve
   strict oracles and shrink-only ratchets; never bypass hooks.
9. Commit and push the reviewed scope. Follow the repository's digest-bound
   release pipeline and fresh-install qualification; tag only the qualified
   source and publish the exact qualified artifacts.
10. Run production deployment, demo down, demo up, then demo verify in the
    requested order. Verify the running version, source and image identities,
    readiness, media and localized public routes.
11. Snapshot current preference values securely, then update every production
    account transactionally to BIP, rich HTML plus cards, occasional exchanges,
    standard portrait 1K JPEG image output with automatic prompt enhancement,
    and ReAct. Verify persisted values and report aggregated counts.

## Evidence

Detailed local receipts and source inventory live under the ignored
`exports/release-v3/` and `exports/lia-motion/` directories. Fresh command
results, actual render metadata, public checks and production receipts must
support the final report. Historical V5 evidence is not V6 qualification.

Story, Why and How remain durable presentations. Public statements distinguish
implemented safeguards and supported standards from legal certification.
