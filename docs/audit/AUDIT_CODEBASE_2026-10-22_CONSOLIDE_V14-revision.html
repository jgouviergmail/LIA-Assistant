LIA demeure un socle industrialisé et très outillé : portes statiques vertes, 45 852 tests unitaires backend et 13 919 tests frontend exécutés frais par la révision, couverture frontend de 87,8 %, chaîne de migrations linéaire, images épinglées, règles d'ingénierie écrites avec une précision rare. La révision conteste néanmoins la note du V14 sur trois points de fond.

  1. Les défauts majeurs ne se ferment pas. Les constats AC-002, AC-003 et AC-004, classés « P0 — avant prochain déploiement sensible » par le V13 le 2 août, sont toujours ouverts après 86 releases ; le V14 ne le signale pas et omet AC-006, également ouvert.
  2. Les défauts sont plus larges que décrits. L'état « livré » déduit de l'absence d'exception touche cinq chemins et non deux — dont la notification d'incident d'autodiagnostic et la confirmation de remise envoyée à l'expéditeur d'un message entre pairs ; l'ombrage des routes Alertmanager existe aussi dans le mode e-mail par défaut.
  3. Des risques significatifs manquaient. Aucune borne d'attente de verrou ni de transaction inactive n'est posée côté PostgreSQL alors qu'un blocage de production de cette classe est documenté dans le dépôt (AC-028, majeur) ; le verrou de rafraîchissement OAuth est sans propriétaire et plus court que sa section critique (AC-029) ; la marge de couverture backend s'est érodée à 0,66 point (AC-030).

À l'inverse, deux défauts d'usage du V14 (focus après suppression SMS, recherche des réglages) ont été corrigés après sa capture et leurs tests passent ; le dernier passage E2E complet observé est vert. La note globale passe de 8,0 à 7,8 : onze périmètres baissent (neuf d'un demi-point, la documentation et l'observabilité d'un point), l'utilisabilité monte d'un point.

Décision de qualité : validation générale non acquise. Quatre constats majeurs sont ouverts, dont trois depuis 81 jours ; la porte de couverture backend n'a plus de marge ; la suite E2E n'a pas été rejouée sous contrôle par la révision. Ce document est une évaluation technique avec réserves, pas une attestation de conformité ni une autorisation de mise en production.

Priorité immédiate (horizon H0) : outiller le registre des constats (AC-031), poser les bornes PostgreSQL (AC-028), corriger les cinq sites de livraison (AC-003) et le verrou OAuth (AC-029), puis fermer les défauts V13 restants (horizon H1). Aucune modification du produit, aucune opération Git d'écriture ni aucun déploiement n'a été effectué : le seul fichier créé est ce rapport.

AC-002 — Fencer de bout en bout les traitements de documents RAG téléversés

Majeur · P1 · E4 · horizon H1 · Ouvert — reconfirmé ligne à ligne

Origine
V13 AC-002 (02/08) → V14 AC-002 → révision — ouvert depuis le 2026-08-02
Faits vérifiés
Pour un document téléversé, aucune source native n'est active : require_source_document sort immédiatement (current_source_worker() vaut None) et ne contrôle donc ni propriétaire ni bail. Le booléen retourné par heartbeat_document est ignoré avant chaque lot d'embedding. L'échange des chunks n'est précédé d'aucune vérification du claim. Le succès écrit status=READY et efface worker_id par une mise à jour ORM sur la seule clé primaire. L'échec appelle fail_or_retry_document, dont l'UPDATE ne filtre que sur id. Le chemin natif (Drive/Gmail) applique déjà le bon motif : SELECT … FOR UPDATE conditionné par worker_id et lease_expires_at > clock_timestamp(). La sonde PostgreSQL à deux sessions du V14 (P02) a montré qu'un échec tardif de A remet PENDING et efface le propriétaire B.
Impact
Après une reprise, un ancien propriétaire peut remplacer les chunks du nouveau, rétablir PENDING, effacer son bail ou marquer READY un travail obsolète : états incohérents, travail répété, dépense d'embedding dupliquée. La fréquence en exploitation n'est pas mesurée.
Cause racine
Le contrat de propriété a été implémenté pour les sources natives seulement ; les opérations du chemin upload s'identifient par l'id du document au lieu du claim.
Contre-vérification et limites
complete_document n'a aucun appelant : le défaut ne porte pas sur elle mais sur la mise à jour ORM réellement exécutée. Les lignes ont été revérifiées sur l'état T1 ; la sonde P02 du V14 est reprise sans être rejouée.
Recommandation
Étendre le motif natif au chemin upload : chaque mutation (heartbeat, échange des chunks, succès, échec/retry) conditionnée par worker_id et un bail non expiré, vérifiés sous verrou dans la transaction qui écrit ; arrêt immédiat sur heartbeat refusé (lever SourceLeaseLost), échange des chunks et règlement d'état atomiques.
Critères d'acceptation
  • Test PostgreSQL à deux acteurs : A réclame, son bail expire, B reprend ; le succès puis l'échec tardifs de A modifient 0 ligne et laissent les chunks de B intacts.
  • Un heartbeat refusé interrompt A avant tout appel d'embedding ou écriture.
  • Annulation, crash après effet et reprise par le reaper couverts ; aucune baseline relevée.

import os
import re
import subprocess
import sys
from pathlib import Path

FR = set("le la les des du une et est sont pour avec dans sur pas qui que ne cette ces aux leur être fait".split())
EN = set("the and is are for with in on not which that this these to be of it its was by".split())
WORD = re.compile(r"[a-zàâçéèêëîïôûùüÿœæ']+")
FENCE = re.compile(r"```.*?```", re.S)
INLINE = re.compile(r"`[^`]*`")
result = collections.Counter()
by_dir = collections.defaultdict(collections.Counter)
examples = collections.defaultdict(list)
for raw in files:
    if not raw:
        continue
    rel = raw.decode("utf-8")
    if not rel.endswith(".md") or rel.startswith("docs/audit/"):
        continue
    text = (root / rel).read_text(encoding="utf-8", errors="replace").lower()
    text = INLINE.sub(" ", FENCE.sub(" ", text))
    words = WORD.findall(text)
    fr = sum(w in FR for w in words)
    en = sum(w in EN for w in words)
    total = fr + en
    if total < 30:
        lang = "short"
    elif fr / total >= 0.6:
        lang = "fr"
    elif en / total >= 0.6:
        lang = "en"
    else:
        lang = "mixed"
    result[lang] += 1
    top = "/".join(rel.split("/")[:2])
    by_dir[top][lang] += 1
    if len(examples[lang]) < 3:
        examples[lang].append(rel)
print("markdown docs by dominant language:", dict(result))
for d, c in sorted(by_dir.items(), key=lambda x: -sum(x[1].values()))[:12]:
