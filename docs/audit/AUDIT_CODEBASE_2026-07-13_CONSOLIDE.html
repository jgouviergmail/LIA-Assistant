1. Verdict exécutif

Progrès démontrés

  • La chaîne Alembic atteint réellement l’unique head 423c346b3f03 sur une base PostgreSQL vierge.
  • La CI couvre maintenant les trois racines de tests, les migrations, la couverture frontend, Python 3.13, les cycles, la complexité, le typage, l’i18n et l’observabilité structurelle.
  • Les défauts scheduler, TTS, embedding, Psyche, Places, date d’export, build web et cycle agents↔telephony ont des corrections et tests cohérents.
  • La release est bloquée sans CI verte et le déploiement vérifie désormais la readiness.

Réserves bloquantes

  • Le contrôle backend courant échoue sur Ruff/Black ; la suite rapide parallèle a produit cinq échecs non reproductibles isolément.
  • Les workflows RAG et téléphonie restent process-local et peuvent perdre ou masquer un échec après changement d’état.
  • alembic check échoue sur de nombreux écarts ; le job de replay l’omet explicitement.
  • Le budget maximal de connexions est de 288 pour 195 slots utilisables.
  • La couverture frontend reste proche de 13 %, sans E2E navigateur ni campagne WCAG formelle.
Contre-analyse du déploiement. Le succès mensuel de task deploy:prod sous Windows est pleinement compatible avec la preuve actuelle : le chemin Windows utilise bien PowerShell et fonctionne. Le défaut résiduel vise uniquement la branche Unix/macOS officiellement publiée, dont l’étape finale appelle encore cmd /c, ainsi que le mode -DryRun qui exécute encore des opérations distantes. Le présent audit ne réintroduit donc pas l’ancien faux diagnostic sur un script standalone qui n’est plus la voie réelle.

2. Référentiel, méthode et réserves

L’évaluation est structurée par le modèle qualité produit de l’ISO/IEC 25010:2023, les faiblesses structurelles de l’ISO/IEC 5055:2021, la description d’architecture de l’ISO/IEC/IEEE 42010:2022, les processus de test de l’ISO/IEC/IEEE 29119-2:2021, et WCAG 2.2, également publié comme ISO/IEC 40500:2025. La sécurité est explicitement hors périmètre : aucun constat, test ou score de ce domaine n’entre dans cette note.

Procédure aveugle

  • Lecture intégrale du rapport consolidé précédent, puis vérification sur le snapshot actuel par symbole et flot de contrôle.
  • Aucune consultation de l’index Git, d’un diff ou de l’identité des fichiers stagés.
  • Triangulation code + configuration + tests + comportement réel ; un commentaire ou un test de caractérisation n’est jamais une preuve suffisante.
  • Recherche systématique de faux positifs, puis recherche de faux négatifs autour des corrections.

Barème

  • 9–10 : maîtrise industrielle démontrée, dette marginale.
  • 7–8,9 : solide, contrôlé, réserves non bloquantes.
  • 5–6,9 : fonctionnel mais dette ou assurance insuffisante.
  • <5 : risque structurel ou fonctionnel incompatible avec une assurance élevée.

La note globale est la moyenne arithmétique des 24 périmètres. Les ratchets qui figent une dette ne valent pas résorption de cette dette.

Réserves : pas d’appel à un fournisseur externe réel, pas de charge multi-worker prolongée, pas de déploiement sur la production, pas de test lecteur d’écran ou navigateur réel. L’audit statique WCAG ne constitue donc pas une certification de conformité. Les numéros de ligne sont ceux du snapshot observé et peuvent dériver.

6. Faux négatifs nouveaux établis

Ces points n’étaient pas des variantes sémantiques des constats antérieurs : chacun possède une contre-preuve spécifique. Ils sont numérotés F042 à F045 et inclus dans le registre de remédiation.

F042 — équivalence Alembic absente

Le replay atteint head, mais alembic check échoue immédiatement avec un volume important d’opérations proposées. Le script documente explicitement l’omission de cette propriété.

F043 — gate backend non déterministe et rouge

Ruff et Black échouent. La suite rapide parallèle échoue sur cinq tests de middleware qui passent 10/10 isolément : l’état global ou l’environnement n’est pas correctement isolé.

F044 — ratchets substituables

Les guards accessibilité et React ne figent qu’un total. Corriger une violation puis en introduire une nouvelle ailleurs conserve 47 ou 34 et laisse la CI verte.

F045 — interactions custom hors filet statique

Le carrousel écoute les flèches au niveau document, chaque instance réagit sans focus ; la carte Hero est souris-only et des champs téléphonie n’ont qu’un placeholder.

Deux autres fenêtres sont rattachées à leur constat parent : F001 compte comme réussis des documents dont process_document a absorbé l’exception ; T1 peut marquer l’appel terminé avant une notification qui échoue, puis neutraliser le retry à cause de cet état terminal.

10. Conclusion d’audit

Conclusion impartiale : les corrections stagées ne sont ni cosmétiques ni surévaluées. Elles ferment quinze points en comptant T2, dont plusieurs risques d’exécution importants. La hausse de 6,4 à 6,7 est justifiée.
Conclusion exigeante : le snapshot actuel ne mérite pas encore une qualification « prêt à promouvoir », car ses gates backend sont rouges et plusieurs propriétés critiques ne sont pas garanties par les tests verts : durabilité, exactitude des états terminaux, équivalence du schéma, exhaustivité CI et accessibilité réelle. Les baselines actuelles sont utiles pour empêcher l’aggravation, mais elles ne doivent pas être confondues avec une conformité industrielle acquise.
