SECTION 2 — THEMES (the ordered ladder: classify by SUBJECT)
=================================================================

The four themes are told apart by WHAT the directive is ABOUT — never by how it is
grounded. EVERY theme's evidence is a past moment; a `BECAUSE` clause citing one is
therefore NOT a signal of misclassification. Ask the questions in order and stop at
the first YES; this is the same ladder the extraction prompt uses.

────────────────────────────────────────────────────────────────
1. **self_reflection** — MY OWN DELIVERY
About MY tone, register, pace or posture, grounded in a user reaction to something
I said. It stays `self_reflection` even though the user's reaction is a specific
past moment — the SUBJECT is my delivery, not a fact I got wrong.
Example:
  WHEN my reply turns sharp → DO reformulate before sending (BECAUSE the user told
  me my tone put him off).

2. **ideas_analyses** — TOPIC-INDEPENDENT SIGNAL
A reading of a signal whose meaning holds whatever the subject is. The normal
evidence is the same signal seen on two DIFFERENT subjects; it does not need to
have been stated. Rare, but do not discard it for lack of an explicit statement.
Example:
  WHEN the user introduces a new topic with a short transition word
  ("bon", "bref", "anyway") → interpret it as exiting one thread and opening
  another, NOT as agreement on the previous one.

3. **user_observations** — STABLE TRAIT OF THE USER
A preference or trait of the user, stated or demonstrated at least twice.
Example:
  User consistently asks for the cost / time / trade-off side of a recommendation
  → surface it without being prompted.

4. **learnings** — LESSON ABOUT THE WORLD OR MY METHOD
A specific moment taught me something repeatable about a fact I got wrong or an
approach that worked.
Example:
  WHEN I cite a film as "available now" → DO verify the release date first
  (BECAUSE I was corrected at T-N for citing an unreleased film).

────────────────────────────────────────────────────────────────
**Reclassification audit** — apply the ladder above, by SUBJECT:

- An entry about the USER's stable traits that is filed under `learnings` because
  its `BECAUSE` cites a correction → `user_observations`.
- An entry reading a signal that holds across subjects, filed anywhere else →
  `ideas_analyses`.
- NEVER reclassify an entry about MY OWN tone, register or posture out of
  `self_reflection` on the grounds that its `BECAUSE` cites a past moment. That
  rule used to exist here and it silently emptied the theme: every well-formed
  `self_reflection` carries such a clause by construction, because the extraction
  prompt REQUIRES a user reaction to ground it.

Never change a theme that is already correct, and never reclassify to chase a
particular theme distribution.

SECTION 3 — YOUR MISSION (execute steps in order)
=================================================================

────────────────────────────────────────────────────────────────
### STEP 1 — MANDATORY DEDUP via active pairwise scan

Surface phrasing differs but semantic topic is what counts. Two entries on
"sober support in vulnerability" and "sober tone in distress" are the SAME
topic — they MUST be merged.

Execute this active scan:

1. List ALL active entries by their UNDERLYING TOPIC (what is at stake), not
   by their phrasing. Group entries that share a topic.
2. For ANY group of size ≥2: this is a duplicate cluster.
   → CREATE one merged, denser entry combining the best of all sources.
   → DELETE all source entries.
3. Threshold for "same topic" is intentionally permissive: if a reasonable
   reader would say "these two say the same thing in different words", merge.
   Don't preserve nuance redundantly.

GUARD: never merge two directives that prescribe DIFFERENT actions, even on the
same topic — distinct actions are not duplicates. Merge wording, not behaviour.

Dedup is the #1 quality lever. Be aggressive on true duplicates, within this guard.

────────────────────────────────────────────────────────────────
### STEP 2 — RECLASSIFICATION audit

Scan every active entry for theme misclassification, using SUBJECT — not the
presence of a `BECAUSE` clause, which every theme has:

1. Read what the directive is ABOUT, then run the Section 2 ladder on it.
2. If the ladder's answer differs from the current theme → propose `update` with
   the corrected `theme` (the rest of the content can stay).
3. If the ladder's answer matches → leave it alone.

Two rules that override any impression of misclassification:
- An entry about MY tone/register/posture STAYS `self_reflection`, whatever its
  `BECAUSE` says.
- An entry reading a signal valid across subjects STAYS (or becomes)
  `ideas_analyses`, even if the user never named the signal.

Don't change themes for entries that are correctly classified. Audit, don't churn.

────────────────────────────────────────────────────────────────
### STEP 3 — PROGRESSIVE REFORMAT (max 5 entries per run)

Identify entries that are narrative prose without actionable content. For up
to 5 such entries:
→ UPDATE to rewrite in the WHEN → DO (BECAUSE) directive format, or in the
   phrasing its theme actually takes — use that theme's example in Section 2
   as the model, OR
→ DELETE if no actionable directive can be extracted.

────────────────────────────────────────────────────────────────
### STEP 4 — EPISTEMIC LIFECYCLE (use the visible metrics)

Reason about each entry using the visible metadata:

- High `ev`, low `co`, high `uses` → propose `confidence=high`.
- Persistent contradictions (`co > ev`) AND directive remains unclear →
  reformulate or delete.
- Stale (`uses=0` AND `last_inj=never` AND `created` > 14 days) → reformulate
  or delete.
- Fresh hypotheses (`conf=low` AND `created` < 7 days) → leave them mature.
- Validated (`conf=high`) → PROTECT.

────────────────────────────────────────────────────────────────
### STEP 5 — STRATIFICATION (synthesise ONLY on genuine convergence)

Look for transversal patterns, but NEVER invent one to hit a count.

1. Group current L1 entries by their UNDERLYING TOPIC, the same way you did
   for dedup (e.g. "factual verification before recommending" might cover
   several entries about checking dates, availability, claims).

2. For a group where the entries genuinely converge on ONE interpretation
   (not merely the same area), you MAY synthesise it:
     (a) Create one L2 synthesis entry (`level=L2`) covering the cluster.
         Format: "I notice that across [contexts], the user consistently
         [pattern] — the unifying interpretation is [synthesis]."
         Then optionally `delete` the absorbed L1 sources, or
     (b) Update one L1 of the group to `level=L2` in the synthesis voice,
         then delete the redundant L1 sources.
   A synthesis must add a real unifying INSIGHT beyond the individual L1s.
   If the entries only share a topic but prescribe DISTINCT actions, leave
   them as separate L1 — that is not a convergence.

3. Zero L2 is the CORRECT outcome when no genuine convergence exists. Do not
   synthesise to satisfy a quota — a forced or spurious L2 is worse than none.

4. Promotion L0 → L1: any L0 raw observation that has RECURRED enough to
   articulate a clean directive should be promoted (theme + WHEN→DO BECAUSE
   per Section 2). An isolated, one-off L0 is NOT promoted — leave it to mature
   or delete it.

5. Demotion: rare; prefer reformulation or deletion.

────────────────────────────────────────────────────────────────
### STEP 6 — STANDARD MAINTENANCE

After dedup, reclassification, reformat, lifecycle, and stratification:
- **Deepen**: Update an entry to add nuance from new evidence.
- **Create**: Write a new cross-theme observation born from rereading.
- **Summarize**: Condense verbose entries.
- **Delete**: Remove obsolete observations.

────────────────────────────────────────────────────────────────
### STEP 7 — PORTRAIT COMPILATION (commit 3 of journal refactor)

After deciding the maintenance actions, compile two portrait views based on:
- the L3 entries (or just promoted) — structural facets
- supporting evidence from L2 patterns and high-confidence L1 directives
- factual signals: usage patterns, health signals, recent conversation if any

The portrait is the synthesis voice — read everywhere LIA speaks.

**`portrait_full`** (~150-220 tokens): faceted portrait of a living person, NOT
a caricature. Distinct facets:
- traits of fond (what is stable)
- current phase (date-bounded if useful)
- contexts (how he shifts: work vs personal, morning vs evening, technical vs
  emotional)
- contradictions (tensions you observe — name them, do not resolve them)
- blind spots / open questions (what you don't yet understand)
- evolution (how he has shifted over time, if visible)

First-person voice, written ENTIRELY in {user_language} — the English
phrasing of the examples in this prompt is structural guidance, never a
language choice ("I notice..." becomes its {user_language} equivalent).
Be specific. AVOID:
- duplicating facts already in the user's psychological profile (memories) —
  focus on synthesis, posture, current phase, contradictions
- promoting transient signals (a single bad day, a week's health activity)
  into "stable traits"
- generic platitudes — every line tied to observed evidence

**`portrait_brief`** (~50-70 tokens): essence in 2-3 sentences, in
{user_language} — posture + current-phase color + 1-2 most-important context
rules. Self-sufficient for secondary flows (notifications, voice, reminders).

If material is insufficient (very few entries, no L3), return empty strings.
Better silent than caricatural.

SECTION 6 — SELF-AUDIT BEFORE OUTPUT (mandatory mental check)
=================================================================

Before emitting JSON, verify:

1. **Dedup completeness**: did you actually merge similar topics? If two
   entries describe the same topic with different wording and you didn't
   merge them, REVISIT.
2. **Reclassification completeness**: did you run the Section 2 ladder, by
   SUBJECT, on every entry? If you used the presence of a `BECAUSE` clause as
   the discriminator, REVISIT — every theme has one.
3. **Stratification honesty**: did you create any L2 WITHOUT a genuine unifying
   insight, or merge L1s that prescribe distinct actions? If so, REVISIT — a
   forced or spurious L2 is worse than none. Zero L2 is fine when there is no
   real convergence.
4. **Portrait quality**: does the `portrait_full` capture the user as a
   living person with distinct facets, OR is it a generic caricature?
   If caricatural, rewrite.
5. **Theme balance is an OUTCOME, never a target**: did any reclassification
   move an entry only because `learnings` felt safer? Undo it. Conversely, a
   journal where three of the four themes are empty is a symptom — re-run the
   Section 2 ladder on the entries you left untouched, by subject.
