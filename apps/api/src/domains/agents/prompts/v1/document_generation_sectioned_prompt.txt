FORMAT FAMILY: SECTIONED OUTPUT (Reports, Whitepapers, Briefs)
- Architecture: Open with an executive framing paragraph (scope and objectives); close substantial documents with a strategic conclusion or structured takeaways.
- Narrative Typography: Within narrative prose, apply the natural punctuation and numerical conventions of the document's language, stated at the end of this prompt (e.g. comma decimals in French prose), while keeping embedded data tables compliant with universal machine formatting.
- Hierarchy: Use a logical hierarchy of `heading` blocks (levels 1, 2, and 3). Every heading must explicitly describe its content. Maintain structural balance: never leave a single isolated subsection under a parent heading.
- Automatic Numbering: do not number your headings and do not write a table of contents. From {toc_min_headings} headings the renderer numbers the headings itself, opens the document on a cover page and adds a table of contents on its own page.
- Block Variety:
  * Flowing narrative -> `paragraph` blocks (one core concept per paragraph, explicit transitions).
  * Enumerable parallel points -> `bullets` (grammatically parallel fragments).
  * Sequential procedures -> `numbered` blocks.
  * Direct citations -> `quote` blocks.
  * Vital alerts / key principles -> `callout` blocks.
  * Structured comparisons -> `table` blocks with an explicit `caption`.
  * A comparison, a trend or a share to see at a glance -> a `chart` block: its `table` holds the data, the table's `chart` says what to draw, its `caption` names the figure. A `table` block whose table declares a `chart` is followed by that figure, so the reader gets both the figures and the picture.
  * The few numbers that carry the message (a result, a growth, a cost) -> a `figures` block: each figure's `value` exactly as it should read (42%, +18%, $1.2M) and a short `label` saying what it measures; never a table's worth of numbers, and never a number the material does not give — not even one you compute from it.
  * A picture -> an `illustration` block, only as the ILLUSTRATIONS rule allows; its `caption` names it.
- Sources: when the material names where its facts come from (articles, reports, web pages), list them in `sources` in the order the text first cites them, each with its `title` and its `url` copied exactly from the material — never an invented or completed address — and cite them in the text as [1], [2]… by their position. No source in the material, no `sources`.
- Table Semantics: write raw values in a `table` (dot decimals, ISO dates) and declare in its `columns` the `kind` (`amount`, `quantity`, `percent`, `date`, `year`, `code`, `text`) and `unit` (a currency code such as `EUR`, or a unit symbol) of each numeric or date column: the renderer writes them in the reader's conventions and aligns them. Never compute a value yourself — declare a computed column with a `formula` and leave its cells empty: names of the table's columns in braces, `+ - * / ^`, parentheses, `ROUND(x, n)`, `ABS`, `MIN`, `MAX`, `SUM({{Column}})`, `AVERAGE({{Column}})`, `RUNNING_SUM({{Column}})`, `PREVIOUS({{Column}})`, and `IF(condition, number, number)` where a condition compares two numbers or a text column with a text in double quotes, combined with `AND`, `OR`, `NOT`, never a column that divides, averages or reads the row above (compare the quantities themselves) — nothing else, at most {formula_max_chars} characters (e.g. `({{Revenue}} - {{Cost}}) / {{Revenue}}` with `kind` `percent`). Ask for a totals row with `total`, and for a grouped `summary` rather than writing a second table: the renderer computes every value.
